# Feature reference

The complete, unabridged list of implemented behavior. The README gives the
readable overview; this file is the precise record.


- DeepSeek Cleanup models are pinned to DeepSeek's own OpenRouter provider endpoint with `provider.only`; third-party hosts are never used for those requests. Other Cleanup model families retain normal OpenRouter routing.
- Foreground microphone recording with a live amplitude waveform and elapsed time.
- Pause, resume, finish, and discard controls in the app and active notification.
- One shared batch pipeline for OpenRouter STT, OpenRouter multimodal audio models, ElevenLabs Scribe v2, and AssemblyAI Universal-3.5 Pro.
- Plain-transcription provider policy: ElevenLabs and AssemblyAI batch/live requests do not enable prompting/keyterms, voice isolation/background filtering, timestamps, speaker diarization/identification, entity detection, audio-event tags, summaries, chapters, or sentiment. AssemblyAI Universal-3.5 Pro receives only the required audio/model fields plus an optional explicit language because it rejects legacy `format_text`/`punctuate` switches even when false. OpenRouter multimodal is the sole intentional prompt-based exception because its chat endpoint requires a transcription instruction.
- Smart wire format: normal recordings upload their archived M4A directly; MAI-Transcribe 1.5 alone receives a temporary MP3 send copy. M4A and MP3 remain manually selectable.
- Native audio import from the Notes upload button and Android's share sheet. MP3, M4A, and WhatsApp OGG/Opus stay byte-for-byte unchanged, become a History item immediately, and are transcribed once automatically.
- Share/import deep-linking opens the new Note directly. It shows `Transcribing…`, briefly confirms `Transcribed`, then exposes the normal editable transcript, player, re-transcribe, export, and delete actions.
- Configurable automatic fallback model. Every failed primary-model request is retried once with the fallback, including recordings finished from the app, notification, or widget.
- Dynamic OpenRouter catalog plus maintained official ElevenLabs Scribe v2/batch and realtime entries. The generic ElevenLabs `/v1/models` fetch is intentionally not used because restricted STT keys can reject that unrelated catalog scope with HTTP 401. AssemblyAI's current documented batch/live STT families are likewise maintained because AssemblyAI does not expose a public model-list endpoint.
- Provider-isolated catalog retention: OpenRouter STT and multimodal/text each keep an atomic last-known-good slice. Automatic refresh is limited to once per six hours after a complete OpenRouter refresh; the visible refresh remains a force refresh.
- Model-aware language hints: known STT families use provider-published language profiles; unknown future models fall back to Android's complete ISO 639-1 catalog.
- Model pricing normalized to one hour of source audio, including an explicit estimate label for token-priced models.
- Editable result field, automatic clipboard copy, manual copy, and saved edits.
- Voice-directed cleanup on Home, Note details, and the voice keyboard. It records a private temporary instruction with the Main-app transcription model, sends the complete current text plus that instruction to one configurable OpenRouter text model, and replaces the complete field. It creates no Note, clipboard event, or recording notification.
- Automatic cleanup on every finished transcription, in the app and the keyboard alike. **Off** inserts the raw transcript and makes no text-model request; **Clean** (the default) strips fillers, false starts and self-corrections, fixes punctuation and capitalization, and carries out spoken commands such as `new paragraph`, `neuer Absatz` or `scratch that` instead of writing them down; **Polish** additionally smooths spoken sentences into readable prose and paragraphs; **Concise** tightens that prose as far as it goes, cutting repetition and detours while keeping every fact, name and number; **Formal** and **Casual** move the same content into a professional or a relaxed chat register without inventing greetings, sign-offs, or emoji; **Notes** restructures the dictation into compact bullets with action items of their own; **Prompt** reshapes a dictated request into one clear instruction for an AI. Every prompt opens by framing the transcript as material to rewrite rather than a message addressed to the model, because a dictated question arrives as a chat user turn and would otherwise be answered instead of rewritten; the only instructions ever obeyed are the spoken formatting commands. Each mode owns an editable system prompt, and only the selected mode's prompt is ever shown. Just the edits are stored — a mode left alone, or put back to its default, keeps following the shipped prompt and picks up later improvements. It shares the Cleanup model with the spoken Edit key but has its own reasoning effort, because it runs on every recording rather than on a rare edit. It is deliberately failure-transparent: a provider error, missing key, or blank answer returns the raw transcript instead of losing the recording. Live streaming models are excluded — their text is inserted as it arrives, so a rewrite landing afterwards would fight the user.
- Key-aware model selection. The app defaults to AssemblyAI Universal-3.5 Pro and the keyboard to ElevenLabs Scribe v2, but a stored model whose provider has no key is replaced per request in the order AssemblyAI → ElevenLabs → OpenRouter. The fallback is always OpenRouter Whisper Large V3 Turbo, and an install holding only an ElevenLabs or AssemblyAI key gets no fallback at all rather than a second request that cannot succeed.
- Optional silence trimming before upload. The send copy is normalized (`speechnorm`, so a quiet microphone still meets one fixed threshold) and its pauses are cut in the same pass that produces the wire format. Providers bill wall-clock audio, so this is cheaper and uploads less; it is skipped under four seconds or when it would save less than 6%, and the archived recording keeps its pauses. Switchable off in Behavior because it costs one short encode per request.
- Running usage totals per API key in Settings: transcribed minutes, request count, and cost, expandable to a per-provider breakdown. Kept separately from Notes because clearing notes should not erase what was spent, and failed or re-transcribed audio costs money without leaving a note. Only OpenRouter reports a real per-request price; ElevenLabs and AssemblyAI totals are derived from the catalog rate and marked `~`.
- Cleanup defaults to DeepSeek V4 Flash 0731 with reasoning off. The live OpenRouter text catalog, token prices, reasoning effort, editable system prompt, and minimum meaningful instruction length are available in collapsed Cleanup settings. The default prompt keeps the hard output contract (complete replacement text, no commentary, no Markdown fences) but deliberately allows the obvious small fixes an instruction implies and asks for the most reasonable reading of an ambiguous one instead of returning the text unchanged. A stored copy of the earlier, stricter default is upgraded on load; an edited prompt is never touched. The length defaults to eight Unicode words; shorter or punctuation-only STT artifacts are silently discarded before any edit-model call, and `0` disables the filter.
- Local transcript history with lazy row composition, an in-place title/transcript search, total archived-audio size in the fixed-height Notes header, title/pin actions on long press, edit, copy, delete, clear, waveform seeking, ±10-second skip, playback, and source-format audio export.
- One-tap re-transcription of an archived voice note with the currently selected model (and the same automatic fallback).
- Last audio retained after an API/network failure so it can be retried. A new recording replaces it.
- Optional permanent archive for failed recordings. When enabled (the default), failed audio appears in Notes with its error, download/delete controls, and the same current-model re-transcribe action instead of being replaced by the next recording.
- Every successful recording archived privately with its History item and playable in the app.
- Android Keystore-encrypted OpenRouter key plus encrypted Android cloud/device-transfer backup for settings, Notes metadata, and archived audio. The non-restorable API key is deliberately excluded.
- System, light, and dark themes across the app and widget with a deliberately monochrome UI.
- Persistent quick-record notification (optional), restored on app resume, reboot, and package update. Its compact single-line custom body toggles recording without opening an Activity; Android still owns notification-shade animation.
- Minimal voice input method whose complete footprint dynamically targets 40% of the display height, with Android's globe/collapse strip deducted from the app-owned view and a 236 dp safety minimum. Its recorder row is shifted upward by one half of that system-strip height so it is optically centered within the keyboard rather than the combined keyboard-plus-SystemUI area. It includes a full-width in-keyboard model browser, a 56 dp floating close bubble positioned safely above Android's globe strip, app/system theme parity, a 184 dp efficient blue amplitude-reactive microphone with a deliberately small centered app vector whose pressed and hovered feedback is masked and radius-limited to the 128 dp optical exclusion zone instead of the full 184 dp touch target, release-inside background gestures, Abandon plus batch-only Pause, a selection-aware accelerated hold-to-delete key in the idle/live right slot, tap-the-microphone-to-finish behavior, direct insertion into the active text field, and Setup shortcuts for Android's required keyboard enable/switch flow. Batch IME recordings carry a unique request ID, so a terminal result from an older editor or recording can never be inserted into the newly focused field. IME results deliberately bypass automatic clipboard copy and its `Note copied` toast because the result is already inserted. Live sessions use the same global recording/processing state, notification, widget, and Notes lifecycle as batch sessions; accepted sessions archive the exact transmitted PCM stream as a playable WAV without a second capture or conversion.
- The IME outer controls are 68 dp and responsively centered between a 128 dp optical exclusion zone around the middle control and each real device edge. Both sides use two-slot columns with a 12 dp vertical gap. Idle shows code-drawn, bounds-centered Space/Delete glyphs; the voice Edit control is below Space on the left, while the thumb-priority Enter/Send control is below Delete on the right. A symmetric bottom row carries Back and Forward. Android gives an IME no access to a host app's undo stack, so the keyboard keeps its own: the full field is captured immediately before and after each of its own operations — inserting a transcript, an automatic cleanup, a spoken edit — and stepping back writes an earlier capture into the field. Single keystrokes are deliberately not recorded, because each snapshot costs a binder round trip and nobody wants to undo one space. The stack holds 20 steps, is dropped when the editor changes, and lapses two minutes after the last edit so it cannot silently restore text the user has long moved past. Holding Space for 300 ms opens a punctuation flyout with `.`, `,`, `:`, `-`, `(`, and `)`; `!` and `?` are deliberately absent because dictation already produces them. It is an elevated pill in the same round language as the controls, with a single accent coin under the finger, and it unfolds to the right from the Space column into the empty band above the controls, because the 184 dp microphone reaches far past its painted circle and a menu on the key's own row would sit on top of it. The gesture stays on the Space key: the cell straight above the finger is armed on open, so a still release inserts the period, sliding sideways picks another symbol, and sliding well below the key cancels without inserting anything, including the space. Cells shrink and the pill clamps its position rather than reaching past a narrow keyboard edge. Enter follows `EditorInfo`: explicit Search, Go, Send, Next, Previous, Done, and custom actions call the editor action; multiline, `NO_ENTER_ACTION`, and unspecified fields receive a newline. The Enter control uses the same neutral surface as the other outer controls and is hidden while recording, processing, or voice-editing. Cleanup stays neutral instead of turning blue, retains Delete during capture/processing, changes `✦` to `✓`, shows `EDIT · 00:xx`, and expands the same white silhouette by up to 22% with volume at up to 50% alpha. The second tap finishes and only the final whole-field replacement is inserted.
- Responsive homescreen widget:
  - Idle: one unambiguous record button and a quiet waveform.
  - Active small: live waveform, discard, and a white Accept button; tapping the remaining body also finishes.
  - Active medium/large: live waveform, pause/resume, discard, and a white Accept button.
  - Large: controls, state, waveform, and latest transcript preview.
  - Density-native, center-cropped waveform rendering keeps bar geometry sharp and constant instead of squeezing it when controls change.
- Horizontal swipe navigation with a page-aware Android Back stack and lightweight spring button feedback.
- Wi-Fi-only upload option, provider-formatted ISO 639-1 language presets, auto-copy, and haptics.
- Collapsed advanced settings for fallback selection, permanent failed-audio recovery, and AAC capture sample rate, bitrate, and mono/stereo channels.
- White adaptive icon with a filled black/charcoal microphone and no internal decorative bars.
- Warm off-white/ink visual system with a single signal-lime accent and dedicated line icons.
